# Shared components

Components used by more than one page. A component used by only one page lives
under that page instead (see `../pages/CLAUDE.md`).

## Anatomy

Every component is a folder named after it, and these files change together:

```
Button/
  Button.jsx          the component (default export) and its *_VARIANTS map
  Button.css          its styles, imported at the top of Button.jsx
  Button.figma.ts     Code Connect mapping to the Figma component
  Button.states.jsx   the states worth showing, for the generated mock
  Button.mock.html    generated by `npm run mocks:build`, never edited
  Button.test.jsx     its tests
```

When you change a component's props or variants, update `.figma.ts` and
`.states.jsx` too, then run `npm run mocks:build`. A missing `.figma.ts` fails
`npm run figma:check`; a stale mock fails `npm run mocks:check`.

## Copy these

- **Variants:** `Badge/Badge.jsx` and `Button/Button.jsx`. Export a
  `NAME_VARIANTS` object of string values, keep a `VARIANT_VALUES` set, and fall
  back to the default variant for an unknown value. Never throw on a bad
  variant.
- **Controlled and uncontrolled input:** `Input/Input.jsx`. Accept `value` or
  `defaultValue`, call both `onChange(event)` and `onValueChange(value, event)`.
- **Composition:** `Breadcrumb/Breadcrumb.jsx` (uses `Icon`).

## Conventions

- **Function components**, default export, props destructured with defaults in
  the signature. Always accept `className` and append it:
  `` className={`badge ${variantClass} ${className}`.trim()} ``.
- **CSS class names are BEM-style:** `.badge`, `.badge--accent` (modifier),
  `.text-input__label` (element). One block per component, named after it in
  kebab-case.
- **Styles use tokens only:** `var(--color-*)`, `var(--space-*)`,
  `var(--radius-full)`, `var(--font-*)`. Everything is in `../styles.css`.
- **Native elements first:** a real `<button type="button">`, `<select>`,
  `<label htmlFor>`. They bring accessibility and keyboard behavior for free.
- **Icons** come from `Icon` with an `ICON_VARIANTS` value, never an inline SVG.
- **No data fetching** in shared components. They take data as props.

## Usage docs

`docs/components/<Name>.md` holds how a component is meant to be used (when to
pick which variant, what not to combine). The design-rules store reads them.
Only Button, Badge and Card have one so far; add one when you add a component.
